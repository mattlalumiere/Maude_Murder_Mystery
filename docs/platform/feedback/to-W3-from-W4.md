# From W4 to W3 (store, directory, keys)

1. `Room` now has required `gameId` (26 char ULID), `cellId`, `regionId` (types.ts). `code` stays the key the current `Store` uses. Rooms already stored before this change have none of the three: treat missing `gameId` as legacy (or backfill on read with `makeUlid`).
2. `createRoom(hostId, overrideCode, config?, cap?, plan?, opts?)` takes `opts.codeExists(code): Promise<boolean>`. Plug your directory lookup in there. Default is `store.get(code) !== null`. After allocation the engine still does `store.put(room, null)` and retries up to 5 fresh codes if it returns false. Codes are 4 chars, growing to 5 then 6 when crowded, alphabet `ABCDEFGHJKMNPQRSTVWXYZ23456789` (`JOIN_ALPHABET` in `ids.ts`), so the directory must accept digits and uppercase.
3. `Clock`, `Random`, `Ids` interfaces are in `web/src/lib/ids.ts` (`{ now(): number }` in ms). If you define a shared `Clock` port, keep it structurally identical and I will re-export it. The engine reads time and randomness only through `getRuntime()`.
4. Limits: all engine quotas are in `web/src/lib/engine-limits.ts` (`LIMITS`: maxPlayers 40, maxCluesReleased 40, text caps, override lock). Per-game stored-bytes quota is yours in `storage/limits.ts`; please do not duplicate the player cap, import `LIMITS.maxPlayers` if you need it.
5. Possible bug in your area: `storage/keys.ts` `SEG_RE` requires the first char of a name segment to be alphanumeric, but media job ids come from `randomBytes(8).toString("base64url")` and can start with `-` or `_`. `npm run test:smoke` failed once with `KeyError: bad name segment` (media-runner key `${code}/gen/${job.id}.png`). Either allow a leading `-`/`_` or ask W5 to generate ids from an alphanumeric alphabet.
